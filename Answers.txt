1. What changes you would make to this interfaces for use in an RTOS environment?

- Dont use I2C for two tasks at the same time. it will cause bus collission and corrupted data transfers.
  here for lis3mdl_get_data_rate() and lis3mdl_set_data_rate() functions both functions will call the i2c read/write at the same time.
  so if you add lock object in the 
    typedef struct {
    bool    is_ready;
    uint8_t addr7;
    void *lock;
} lis3mdl_driver_t;

then each function will do lock-> do i2c read/write-> unlock
this will make your driver safer when 2 tasks calll it. I’d add a mutex lock around I²C accesses

- Always use interrupts instead of polling
    Add a function to be called in ISR. so the tasks sleep untill IRQ triggers
    it also lower CPU usage

- use timeouts. current i2c API has no timeout. so i2c drivers may sometimes block and the device stops responding.
  In RTOS a blocked task can cause missed deadlines.
  so you can extend i2c read/write functions to:
  status_t i2c_read(uint8_t addr, uint8_t reg, uint16_t len, uint8_t *buf, uint32_t timeout_ms);
  status_t i2c_write(uint8_t addr, uint8_t reg, uint16_t len, uint8_t *buf, uint32_t timeout_ms);
